# ARCHITECTURE — shortcut-lens

This document defines structure, boundaries and data contracts. Claude Code may refine details
(with a DECISIONS entry) but must not change the zone boundaries or the data contracts without
asking the human.

---

## 1. The two zones (the most important idea in this codebase)

The whole project is about finding failures **without** group labels and then **checking** the
answer **with** them. If label-free code can see group labels, every result is contaminated. So the
code is split into two zones, and the boundary is enforced mechanically.

```
                    ┌──────────────── composition root ────────────────┐
                    │  cli.py  — builds datasets via build/, injects    │
                    │  them into stages, wires artefacts together        │
                    └───────────────────────────────────────────────────┘
       ORACLE ZONE  (may read group labels)          LABEL-FREE ZONE  (must not)
       ─────────────────────────────────────         ──────────────────────────────────
       build/          dataset construction,          data/            public tables, transforms,
                       planting, rendered datasets                     ImageDataset protocol
       oracle/         the ONLY reader of             models/          backbones, feature extraction
                       oracle.parquet                 training/        ERM loop
       evaluation/     scoring vs ground truth        embeddings/      model-space and CLIP embeddings
       verification/   interventions, reliance        discovery/       slice discovery + confirmation
       mitigation/oracle_ref/  DFR-oracle,            naming/          vocab + caption namers
                       oracle-tuned references        mitigation/label_free/, mitigation/selection.py
       report/         tables and figures
                                   SHARED, PURE (no labels, no I/O side effects beyond files)
                                   types.py  config.py  manifest.py  artifacts.py  seeding.py
                                   metrics.py  stats.py  viz/ (plots from dataframes passed in)
```

**Enforcement.**
1. `import-linter` *forbidden* contract: modules in the label-free zone may not import
   `shortcut_lens.build`, `shortcut_lens.oracle`, `shortcut_lens.evaluation`,
   `shortcut_lens.verification`, `shortcut_lens.mitigation.oracle_ref`, or `shortcut_lens.report`,
   directly or indirectly.
2. Datasets are created in `build/` and passed into label-free code by `cli.py`. They implement the
   `ImageDataset` protocol and return exactly `{"image", "y", "example_id"}`. A contract test
   iterates every dataset type and asserts the key set.
3. Label-free stages read `public.parquet` only. `oracle.parquet` is opened only by `oracle/`.

Example `pyproject.toml` fragment:

```toml
[tool.importlinter]
root_package = "shortcut_lens"

[[tool.importlinter.contracts]]
name = "Label-free zone cannot see group labels"
type = "forbidden"
source_modules = [
  "shortcut_lens.data", "shortcut_lens.models", "shortcut_lens.training",
  "shortcut_lens.embeddings", "shortcut_lens.discovery", "shortcut_lens.naming",
  "shortcut_lens.mitigation.label_free", "shortcut_lens.mitigation.selection",
  "shortcut_lens.app",   # the app reads bundle files only, never oracle modules
]
forbidden_modules = [
  "shortcut_lens.build", "shortcut_lens.oracle", "shortcut_lens.evaluation",
  "shortcut_lens.verification", "shortcut_lens.mitigation.oracle_ref", "shortcut_lens.report",
]
```

## 3. Core types (sketch — refine in code, keep the spirit)

```python
# types.py
class ImageDataset(Protocol):
    def __len__(self) -> int: ...
    def __getitem__(self, index: int) -> dict[str, Any]: ...
    # returns exactly {"image": Tensor[3,H,W], "y": int, "example_id": str}

@dataclass(frozen=True)
class Predictions:            # one split of one model
    example_ids: list[str]
    y: np.ndarray             # int  [N]
    y_hat: np.ndarray         # int  [N]
    p_y: np.ndarray           # float [N] probability of the true class
    p_max: np.ndarray         # float [N]
    logits: np.ndarray        # float [N, C]

@dataclass(frozen=True)
class EmbeddingTable:
    space: str                # "model" | "clip"
    example_ids: list[str]
    vectors: np.ndarray       # float32 in memory [N, D]; float16 on disk

@dataclass(frozen=True)
class ClassView:              # input to discovery for one class, one split
    class_id: int
    example_ids: list[str]
    x: np.ndarray             # preprocessed embeddings [N, d]
    correct: np.ndarray       # bool [N]
    p_y: np.ndarray           # float [N]

@dataclass(frozen=True)
class Slice:
    slice_id: str             # f"{method}-{space}-c{class_id}-k{index}"
    method: str
    space: str
    class_id: int
    index: int
    params: dict[str, Any]

class FittedSlicer(Protocol):
    def slices(self) -> list[Slice]: ...
    def scores(self, x: np.ndarray) -> np.ndarray: ...   # [N, n_slices], higher = more in slice
    def members(self, x: np.ndarray) -> np.ndarray: ...  # bool [N, n_slices]

class SliceDiscoverer(Protocol):
    name: str
    def fit(self, view: ClassView, rng: np.random.Generator) -> FittedSlicer: ...

@dataclass(frozen=True)
class NameCandidate:
    slice_id: str
    namer: str
    phrase: str
    score: float
    direction: Literal["positive", "negative"]
    support_n: int | None     # caption keywords only

class Intervention(Protocol):      # oracle zone
    name: str
    def apply(self, example_id: str) -> Tensor: ...
```

Discovery methods live in a plain dict registry in `discovery/__init__.py`:
`DISCOVERERS = {"confidence": ..., "error_kmeans": ..., "domino_em": ..., "failure_direction": ...}`.

## 4. Data contracts (Parquet schemas)

| File | Columns |
|---|---|
| `public.parquet` | `example_id: str`, `dataset: str`, `split: {train,val_a,val_b,test}`, `y: int`, `class_name: str`, `image_ref: str` |
| `oracle.parquet` | `example_id`, `attribute: int`, `group: int` (= 2·y + attribute), `group_name: str` (format `"<class>|<attribute>"`, e.g. `dog|patch`, `landbird|water` — must match keys in `vocab/eval_keywords.yaml`), `is_minority: bool`, planted only: `has_patch: bool`, `patch_x: int`, `patch_y: int`, `patch_size: int` |
| `predictions/{split}.parquet` | `example_id`, `y`, `y_hat`, `p_y`, `p_max`, `logit_0..C-1`, `correct` |
| `embeddings/{space}/{split}.npy` + `.ids.parquet` | row i of the array ↔ row i of ids |
| `discovery/<m>_<s>/slices.parquet` | `slice_id`, `method`, `space`, `class_id`, `index`, `rank`, `size_val_a`, `err_val_a`, `params_json` |
| `discovery/<m>_<s>/scores.parquet` | long format: `example_id`, `split`, `slice_id`, `score`, `member` |
| `discovery/<m>_<s>/confirmation.parquet` | `slice_id`, `n_val_b`, `err_slice`, `err_rest`, `odds_ratio`, `p_value`, `q_value`, `confirmed`, `global_rank` |
| `discovery/<m>_<s>/names_<namer>.parquet` | `slice_id`, `namer`, `rank`, `phrase`, `score`, `direction`, `support_n` |
| `discovery/<m>_<s>/verification.parquet` | `slice_id`, `intervention`, `n`, `fix_rate`, `fix_lo`, `fix_hi`, `control_rate`, `control_lo`, `control_hi`, `verdict` |
| `reliance.parquet` | `direction`, `intervention`, `n`, `break_rate`, `lo`, `hi`; plus `R_net` summary row |
| `mitigation/<method>/{split}.parquet` | same schema as predictions + `method`, `params_json` |
| `results/*.csv` | tidy tables generated by `slens report` |
| `results/final_eval_log.csv` | append-only: `timestamp`, `config_hash`, `run_id`, `method`, `rerun_reason` |

Every loader validates: required columns present, no duplicate `example_id`, split names valid,
embedding ids identical (same order) to the ids they are joined with.

## 5. Stage graph and artefacts

```
build ──► train ──► embed(model) ─┬─► discover ─► confirm ─► name ─┬─► mitigate ─► evaluate --final ─► report ─► export-demo
   │                              │                                 │
   └──────► embed(clip, cached) ──┘          reliance* ◄── train    └─► verify*
```

Artefact layout:

```
artifacts/
├── builds/<dataset>/<build_hash>/public.parquet, oracle.parquet, manifest.json
├── cache/clip/<render_hash>/<split>.npy + ids     # planted CLIP cache keyed by patch spec
└── runs/<run_id>/                                  # run_id = <exp>-<dataset>-<cfghash8>-s<seed>
    ├── manifest.json
    ├── train/ checkpoint_last.pt checkpoint_best.pt history.csv
    ├── predictions/<split>.parquet
    ├── embeddings/<space>/<split>.npy (+ ids)
    ├── reliance.parquet
    ├── discovery/<method>_<space>/<val_mode>/ slices, scores, confirmation, names_*, verification
    └── mitigation/<val_mode>/<method>/ predictions + params
```

**Idempotency.** Each stage computes an output key from its config hash and the ids of its input
artefacts. If the outputs exist and the manifest matches, the stage is skipped unless `--force`.
The git commit is recorded in the manifest but is not part of the key.

**Manifest fields:** `run_id`, `stage`, `created_at`, `git_commit`, `git_dirty`, `config`,
`config_hash`, `seed`, `inputs` (artefact ids), `python`, `packages` (torch, torchvision,
open_clip, transformers, sklearn, numpy versions), `hardware` (device name, CUDA version),
`duration_s`, `frozen_vocab_sha256` (naming only).

## 6. Configuration

YAML files validated by Pydantic. Experiment configs compose smaller ones. The config hash is the
sha256 of the canonical JSON of the fully resolved config (sorted keys), truncated to 8 characters
in run ids.

  epochs: 20

## 8. Algorithms: implementation notes

- **Planting positions:** `rng = np.random.default_rng(hash64(example_id, build_seed))`; the patch
  is fully inside the 224×224 canvas. Horizontal flips in training move the patch; that is intended.
  A flip is a bijection, so a patch fully inside the canvas stays fully inside and its pixel count
  is unchanged after flipping (verified by a property test in `build/planting.py`).
- **Augmentation:** resize/crop happen once at build time; training augmentation is horizontal flip
  only (random crops could cut the patch out and silently change ρ).
- **PCA:** fitted on `val_a` embeddings of the relevant space, after L2 normalisation.
- **domino_em (per class):** diagonal Gaussians on PCA features + Bernoulli on `incorrect`.
  E-step: `log r_ik ∝ log π_k + log N(x_i | μ_k, diag σ_k²) + w · log Bern(e_i | θ_k)`.
  M-step: weighted means, variances (with floor 1e-6), mixing weights, `θ_k` = weighted error rate.
  Initialise with k-means++ (seeded). With `w = 0` it must match sklearn's diagonal GMM.
  Slices ranked by `θ_k`. Scores are responsibilities.
- **error_kmeans:** scores are negative distances to the slice centroid; members are points whose
  nearest centroid is the slice.
- **failure_direction:** `LinearSVC(class_weight="balanced")` on incorrect vs correct; score is
  the decision value; members are points above the threshold that keeps the top q% on `val_a`
  (q from config).
- **confirm:** 2×2 table (in slice / not) × (incorrect / correct) on `val_b`; one-sided Fisher exact
  test (greater); BH over all candidates of a (method, space, val_mode) run.
- **select_combo (FR-C4):** label-free selection of which (method, space) combination feeds naming,
  verification and `dfr_discovered` — the combination whose top confirmed slice has the largest
  error-rate lift over the rest of its class on `val_b`, tie-break by smallest q-value. Uses only
  `val_b` error rates and q-values, no group labels (D-024). All combinations still appear in the
  appendix table (T2); gate G4's oracle-best-of-all framing is a sanity check only, never the
  selection rule.
- **last_layer:** full-batch L-BFGS logistic regression in PyTorch on standardised embeddings
  (standardisation statistics from `val_a`), optional L1 via proximal step or L2, optional L2 pull
  towards the ERM head, sample weights. Checked against sklearn on unweighted L2 problems.
- **DFR averaging:** fit on `n_subsets` group-balanced random subsamples (true groups or
  pseudo-groups), average the weight vectors.
- **AFR weights:** `w_i = exp(−γ · p_y,i)`, normalised so each class has equal total weight.

## 10. Devices and performance

- `device: auto` → CUDA if available, else CPU. Smoke configs force CPU.
- T4 notes: use fp16 autocast + GradScaler; PyTorch SDPA/standard kernels only.
- DataLoader: `num_workers` from config (Kaggle ≈ 4), `pin_memory=True` on CUDA,
  `persistent_workers=True` for training.
- Everything after embeddings (discovery, confirmation, naming scoring, mitigation, evaluation,
  reporting) must run on a laptop CPU in minutes.
